# 电商平台运维政策（v1）

## 3.1 系统维护
平台例行维护为每周日凌晨3:00-5:00，期间部分功能（下单、支付）将暂停10分钟，紧急修复不计维护时间，维护完成后将发布维护公告。

## 3.2 异常码
常见异常码：400-参数错误、500-系统内部错误、503-服务不可用、504-网关超时，具体含义请参照《技术异常码手册》。

## 3.3 接口限流
单用户单接口每秒限制10次，单接口总频率每分钟不超过100次，超限将返回429状态码并记录日志，长期超限将冻结接口调用权限。

## 3.4 联调测试
跨系统数据接口联调使用测试环境而非生产环境，提供Mock测试数据，校验响应字段、响应时间、异常码，联调结束后需进行安全审计和性能压力测试。

## 3.5 灾备恢复
双机热备份，故障自动切换用时<5分钟，人工恢复备份需2-4小时，最近1天的交易数据可恢复，超过1天的数据需提工单申请。

## 3.6 日志保存
日志按天分库存储，保存180天在线查询，180-365天归档至冷存储，超过365天销毁，所有日志必须脱敏处理（脱敏字段：手机号后4位、银行卡后4位、真实姓名）。

## 3.7 蓝绿部署
系统升级采用蓝绿部署，旧版实例保留回滚能力，数据库增量备份前置，升级完成后自动健康检查通过方可切换流量。

## 3.8 权限管理
角色权限遵循最小权限原则，超级管理员拥有全权，业务角色仅具备模块增删改查权，系统管理员仅具备配置权限，禁止直接操作生产数据。

## 3.9 链路追踪
使用统一链路ID（trace_id），贯穿用户下单-支付-物流的全过程，支持在日志系统检索、查看每个环节的请求参数、返回结果、耗时情况。

## 3.10 容灾演练
每季度一次容灾演练，内容包括故障切换演练、数据恢复演练、业务中断应急演练，演练结束后需提交演练报告并改进应急预案。
