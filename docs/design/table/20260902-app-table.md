# t_app 应用配置表设计

> 版本：v1.0 ｜ 状态：**已批准** (2026-09-02 计划审批通过) ｜ 依据：《开发排期》W09 应用工厂 · 客服迁移 · P2 收口；CLAUDE.md 设计文档铁律

---

## 1. 基本信息

| 项 | 值 |
|----|----|
| 表名 | t_app |
| 所属层 | L7 数据层（`com.agent.data.app`） |
| 用途 | 应用注册表：承载"应用 = 场景配置"八项配置（角色/Prompt/知识库/工具/记忆/评测集/转人工/配额） |
| 生命周期 | 与 t_agent_run / t_workflow_instance 同级，随 `spring.sql.init.mode=always` 幂等 DDL 启动执行 |

## 2. 设计目的

**要解决的问题**：当前 appId 只是透传字符串（CS_AGENT/TR_BOOKING），无注册表、无配置载体——Prompt 四处硬编码、工具授权无 per-app 白名单、配额靠 `AgentConfig.of(appId)` 前缀魔法、无启停能力。W09 要求"应用=场景配置"可配置化装配。

**不做会怎样**：新场景接入仍需改代码（排期 G2 目标"新场景实测 ≤2 周"无法达成）；P2 铁律"Prompt 不得硬编码"无法收口。

**设计原因**：启停状态须在线修改且重启不丢、管理 API 需分页直查 → 配置落 DB（与 Workflow "DB 为唯一权威" 先例一致）；种子内容走 classpath `app-seeds/*.json` 保 JSON 可读可版本化（沿用 WorkflowFlows 读法）。

## 3. 字段逐项说明

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGSERIAL | PK | 主键 |
| tenant_id | VARCHAR(64) | NOT NULL DEFAULT 'GLOBAL' | 租户维度（GLOBAL=平台内置应用） |
| app_id | VARCHAR(64) | NOT NULL | 应用标识，如 cs_customer_service / tr_booking |
| name | VARCHAR(128) | NOT NULL | 应用名 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'CREATED' | CREATED / ENABLED / SUSPENDED |
| config_json | JSONB | NOT NULL | **八项配置**（见下） |
| version | INT | NOT NULL DEFAULT 1 | 配置版本（行级回滚参考） |
| created_at / updated_at | TIMESTAMPTZ | NOT NULL DEFAULT now() | 时间戳 |

**config_json 八项 schema**：

```json
{
  "role":      { "name": "企业客服", "description": "..." },
  "prompt":    { "system": "...", "userTemplate": "...", "contextBudget": 8192 },
  "kb":        { "kbType": "TENANT|NONE", "sourcePrefix": null },
  "tools":     [{ "name": "policy_query", "permission": "READ" }],
  "memory":    { "enabled": false, "fieldWhitelist": [] },
  "eval":      { "ref": "cs_golden_v1", "metrics": { "goldenPassRate": 0.9 } },
  "handoff":   { "enabled": true, "threshold": 0.25, "weights": {...} },
  "quota":     { "maxSteps": 10, "tokenBudget": 32000, "timeoutMs": 300000, "loopThreshold": 3, "maxConcurrency": 5 }
}
```

- `role.name` 必填；`prompt.system` 必填（模板可含 `{maxSteps}` 等占位符，装配时渲染）
- `kb.kbType`：v1 仅 TENANT（绑租户）/ NONE（不绑）
- `tools[].permission`：READ/WRITE；**PAYMENT 不允许出现在白名单**（引擎全局 403 恒锁）
- `handoff.enabled=true` 时 `threshold` ∈ (0,1]、`weights` 三项非负

## 4. 索引设计

| 索引 | 列 | 用途 |
|------|----|----|
| uq_app_tenant_app | (tenant_id, app_id) UNIQUE | 租户内应用标识唯一 |

应用量小（平台内置个位数），单唯一索引即可，无需额外索引。

## 5. 关联关系与约束

- 无物理外键（同 W4 惯例）。app_id 被 t_agent_run.app_id / t_workflow_instance.app_id 以**逻辑外键**引用（现有字段，不新增列）。
- 更新策略：`updated_at` 随更新刷新；`version` 每次配置变更 +1。

## 6. 租户隔离设计（必查）

- t_app 按 `tenant_id` 行级隔离：管理 API 全部读 `X-Tenant-Id`（缺省 default）；列表/详情按租户过滤；GLOBAL 应用对任何租户可见可引用。
- 消费链路（AgentRun.submit 等）按 `(tenantId, appId)` 二元组装配，不跨租户。

## 7. 数据治理影响（必查）

- 无 PII；config_json 含 Prompt 模板与业务配额，属业务配置，无脱敏要求。
- 保留策略：随表生命周期（不删除设计）；版本号提供配置回滚锚点。
- 血缘：t_agent_run / t_workflow_instance 的 app_id 可回溯到该应用当前配置；配置升级（version+1）与运行记录解耦（运行记录不受配置变更影响）。

## 8. 备选方案与放弃理由

| 方案 | 结论 | 理由 |
|------|------|------|
| 纯 classpath `apps/*.json`（不落库） | ❌ | 启停状态无法在线修改、管理 API 无法分页直查、不符合"DB 为唯一权威"先例 |
| 独立 t_prompt 表 + t_app 引用 | ❌ | 双表一致性与 join 复杂度；prompt 复用需求未出现（出现再做，见演进） |
| config_json 用多列拆开存 | ❌ | 八项配置嵌套结构，JSONB 表达自然，字段级查询无需求 |

## 9. 建表 SQL

```sql
CREATE TABLE IF NOT EXISTS t_app (
    id          BIGSERIAL PRIMARY KEY,
    tenant_id   VARCHAR(64)  NOT NULL DEFAULT 'GLOBAL',
    app_id      VARCHAR(64)  NOT NULL,
    name        VARCHAR(128) NOT NULL,
    status      VARCHAR(16)  NOT NULL DEFAULT 'CREATED',
    config_json JSONB        NOT NULL,
    version     INT          NOT NULL DEFAULT 1,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (tenant_id, app_id)
);
```

## 10. 演进预判

- 出现跨应用 Prompt 复用/版本审计 → 抽 t_prompt 表（本设计版本号兼容迁移）
- 知识库细粒度绑定（source 前缀过滤 kb.sourcePrefix）→ RagService.hybridSearch 按前缀加过滤条件（本表新增一字段可承载）
- 多租户自建应用 → app_id 天然带 tenant_id 维度，接口不变
