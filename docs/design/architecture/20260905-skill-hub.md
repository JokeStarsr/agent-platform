## 1. 设计目的

**要解决的问题**：平台现在有"应用工厂（单场景配置）"、"工具市场（单工具）"、"多智能体（Supervisor/Pipeline 编排）"，但**缺少一个面向最终用户的能力包层**——用户说"帮我安排出差 + 写会议纪要 + 查数据"，平台需要把这些能力**组合、路由、预览确认**成一站式"通用 AI 助手"。W14 要求：

1. **Skill Hub**：可安装/卸载/版本化的"技能包"（一个技能 = 一组 Prompt + 工具 + 知识包 + 测试用例）；
2. **通用 AI 助手**：根据用户意图路由到技能 → 调用技能（可能触发多智能体/工具/写操作）→ **写操作先 diff 预览、确认后执行**；
3. **技能发布门禁**：自带测试用例全绿才可上架；
4. **P3 收口**：通用助手跨技能端到端成功率 ≥ 80%；写操作预览确认 100% 生效；平台四场景全景联调。

**不做会怎样**：平台能力碎片化（工具/流程/多 Agent 各自独立，用户无法一站式调用）；写操作无"执行前变更预览"（P3 闸门"写操作预览确认 100%"无法达成）；P3 收口失败。

**范围**：本设计实现 **L3 Skill Hub v1**——①技能包模型与 manifest 规范；②t_skill 安装/版本/启停；③技能发布门禁（测试用例）；④通用助手（技能路由 + 操作预览 diff + 确认执行流）；⑤5 个首发技能。**不做**：技能市场对外分发（内部 Hub）、技能依赖的跨租户共享（平台级技能 + 租户启停）、Prompt 复杂模板引擎（沿用 AppDefinition）。

## 2. 关键架构决策（ADR-20260905-04：技能 = 复用应用工厂的能力组合包）

### 2.1 技能包是"配置组合"而非新执行引擎

```
用户请求 ─► GeneralAssistant（通用助手）
    │ 意图路由（LLM 选技能 or 规则匹配）
    ▼
Skill 解析：manifest → {prompts, tools, kb, orchestration}
    │  → 单技能：直接走 AgentRuntime（复用 W4）
    │  → 组合技能：走 MultiAgentService（复用 W13）
    │  → 工具：走 ToolEngine（复用 W5）
    ▼
写操作 → OperationPreview（diff 展示）→ 用户确认 → 执行
```

- **为什么不是新引擎**：技能需要的"执行"（Agent 循环/多智能体/工具/写操作 HITL）平台全都有了（W4/W5/W13）。Skill Hub 只做"**能力组合 + 路由 + 发布门禁**"，不重复造执行引擎。
- **技能 vs 应用工厂**：应用工厂（W9）是"单场景的单例配置"（一个 appId 一套角色/Prompt/工具）；技能是"**可复用、可组合、可版本化的能力单元**"，通用助手负责把技能路由/组合起来。技能 manifest 可引用应用工厂的 Prompt 模板、工具市场的工具、知识库。
- **不做的方向**：技能作为独立执行引擎跑自己的状态机（与 Workflow/Agent 重复）；技能跨进程分发（内部 Hub，仅平台内可见）。

### 2.2 写操作预览（OperationPreview）是 P3 硬闸门

- 通用助手触发的任何 WRITE/PAYMENT 工具，执行前必须生成**变更预览**（diff/结构化描述：API/参数/金额/影响范围），用户确认后才真正执行（复用 AgentRuntime 的 HITL，但升级为"带 diff 预览的确认"）。
- v1 预览 = 结构化 JSON 展示（`{tool, params, summary, impact}`），前端渲染为"将要做什么"卡片；**任何写操作无确认不执行**（硬约束，P3 闸门 100%）。

## 3. 技能包模型（Skill Manifest）

```jsonc
{
  "name": "trip_advisor",          // 唯一：小写下划线
  "version": "1.0.0",
  "displayName": "差旅助手",
  "description": "结合差旅政策与流程，帮员工规划合规差旅（含审批与下单）",
  "category": "business",
  "prompts": {                       // 引用 PromptCenter 模板 key 或内联
    "system": "你是有差旅政策知识的企业助手…",
    "router": "识别用户差旅意图并生成任务…"
  },
  "tools": ["policy_query", "compare_flight", "compare_hotel",
            "book_order", "cancel_order", "notify_user"],   // 引用工具市场工具
  "kb": ["tc_policy_v3", "tc_payment_v1"],                  // 引用知识库（RAG collection）
  "orchestration": "multi-agent",    // none | agent | multi-agent
  "permissions": ["READ", "WRITE"],  // 技能声明的最大权限（WRITE 触发预览确认）
  "testcases": [                     // 发布门禁：自带测试用例
    {"name": "合规差旅", "input": "帮我订北京到上海出差往返", "expect": "产出合规方案并进入人工确认"}
  ]
}
```

**首发 5 技能**（v1）：

| 技能 | 用途 | 编排 | 写操作 |
|------|------|------|--------|
| `trip_advisor` | 差旅政策咨询 + 方案 + 下单审批 | multi-agent | book_order（预览确认） |
| `data_query` | 自然语言查数据（走 SQL 沙箱只读） | agent | 无（只读） |
| `meeting_notes` | 会议纪要生成与摘要 | pipeline | 无 |
| `email_draft` | 邮件草稿生成 | agent | send（预览确认，接邮件工具） |
| `faq_answer` | 通用知识问答（RAG） | agent | 无 |

## 5. 通用 AI 助手（GeneralAssistant）

### 5.1 执行流程

```
POST /api/assistant/ask {message, sessionId?}
  1. 路由：LLM 把 message 分类到技能（skills 列表 + 描述 → generateStructured 选技能，或规则 fallback）
  2. 装配：取技能 manifest → 组装上下文（prompts + kb 检索 + tools 白名单）
  3. 执行：
       - orchestration=none/agent → AgentRuntime（复用）
       - multi-agent → MultiAgentService（复用）
  4. 写操作：拦截 → 生成 OperationPreview（diff）→ SSE 事件 preview_ready → 等 /confirm
  5. 确认后 → ToolEngine 执行（带幂等键）→ 返回结果
```

### 5.2 接口契约

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/assistant/ask` | 提问（body `{message, skillHint?}`）→ SSE 事件流（routed/preview_ready/answer/done） |
| POST | `/api/assistant/confirm` | 确认写操作（body `{sessionId, previewId, approved}`） |
| GET | `/api/assistant/skills` | 当前可用技能清单 |
| POST | `/api/skill-hub/install` | 安装技能（body manifest 或引用）→ 跑测试用例 → PUBLISHED |
| POST | `/api/skill-hub/{id}/uninstall` | 卸载（OFF_SHELF） |
| POST | `/api/skill-hub/{id}/new-version` | 发新版本 |

## 6. 安全与影响

### 6.1 租户隔离 ★
- 技能平台级共享（读）；写操作预览确认按会话/租户隔离；执行走各层既有租户过滤。

### 6.2 写操作红线
- **通用助手写操作无预览确认不执行**（OperationPreview 硬门禁）；PAYMENT 恒 403；幂等键强制（复用 ToolEngine）。

### 6.3 数据血缘/保留
- 技能版本可回溯（t_skill_version）；助手会话走 agent run 既有 trace；manifest 配置随生命周期不删，OFF_SHELF 保留。

## 7. 备选方案

| 方案 | 结论 | 理由 |
|------|------|------|
| 技能新造执行引擎 | ❌ | 与 W4/W5/W13 重复 |
| 技能不落库（纯代码注册） | ❌ | 版本/启停/门禁需要管理面（同 t_tool_catalog 先例） |
| 写操作不预览直接确认 | ❌ | P3 闸门"预览确认 100%"无法达成 |

## 8. 分步实施

| 步骤 | 内容 | 验收 |
|------|------|------|
| 1 | t_skill + t_skill_version 建表 + Repository + manifest 解析器 | 表幂等，manifest 校验通过 |
| 2 | Skill Hub API（install/uninstall/new-version/list）+ 发布门禁（跑 testcases） | 装技能→测试全绿→PUBLISHED |
| 3 | GeneralAssistant：意图路由（LLM 选技能）+ 装配 + 执行复用 | 选对技能并产出答案 |
| 4 | OperationPreview：写操作 diff 生成 + 确认执行流（SSE preview_ready） | 写操作无确认不执行（P3 闸门） |
| 5 | 5 个首发技能 + 测试 | 每个技能自带测试用例全绿 |
| 6 | P3 指标报告 + 四场景全景联调 + 管理页 `/assistant/` | 通用助手 30 任务 ≥80%（人工判分） |
