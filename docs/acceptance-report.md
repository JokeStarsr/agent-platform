## 5. 已知限制与后续建议

### 已知限制（非阻塞）
| 限制 | 说明 | 缓解 |
|------|------|------|
| LLM 计量为估算 | W17 token 用量基于字符数估算（未读 provider usage） | 已留 TokenMeter 接口，接入真实 usage 即用 |
| Kafka/ClickHouse 未引入 | 计量/看板用 MySQL 聚合表起步 | 日调用 >10 万时演进 |
| 多租户登录未做 | 仅 X-Tenant-Id 头租户隔离（无认证体系） | MCP 网关/W9 已有鉴权先例，可扩展 |
| 微调流水线未搭建 | W18 微调 Go/No-Go 判定：样本不足 1000 条 | 累积标注后启用 LoRA 流水线 |
| OAuth2 第三方登录未做 | 开放平台仅 API Key | 量大后演进 |

### 后续建议（按优先级）
1. **接入真实 Token usage**（LLM provider 返回 usage → TokenMeterService）
2. **PII 脱敏接入 LLM 输出链路**（当前为独立 API，未在 RAG/Agent 输出强制过滤）
3. **注入检测接入请求 Filter**（当前为规则 + API，可在 Access 层启用）
4. **删除级联**（用户删除 → 记忆/向量/缓存/会话清理）
5. **Kafka + ClickHouse 计量管道**（量大后演进）
